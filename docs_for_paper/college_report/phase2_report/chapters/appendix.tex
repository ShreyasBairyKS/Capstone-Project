\chapter{Appendix A: Code Excerpts}
\label{appendix:code}

Listing~\ref{lst:gate} is the per-view rule of the Station 1 quality gate (Eq.~\eqref{eq:gate}), taken from \path{pipeline/decision/gate.py}; the result objects are abbreviated. Listing~\ref{lst:fill} is the fill-ratio computation of Eq.~\eqref{eq:trim}--\eqref{eq:rfill}, taken from \path{pipeline/fill_level/inference/engine.py}.

\begin{lstlisting}[language=Python, caption={Per-view quality gate (abbreviated)}, label={lst:gate}]
def evaluate_view(self, camera_result):
    detections = camera_result.detections
    # 1. No detection above the 0.35 floor
    if not detections:
        return ViewVerdict(verdict=INSPECTION_FAILED, ...)

    # 2. Any defect class at or above the defect threshold
    defect_candidates = [
        d for d in detections
        if self.config.is_defect(d.class_name)
        and d.confidence >= self.config.defect_conf_threshold]
    if defect_candidates:
        top_defect = max(defect_candidates, key=lambda d: d.confidence)
        return ViewVerdict(verdict=REJECT, defect_name=top_defect.class_name, ...)

    # 3. Certified pass needs good_cap at or above the pass threshold
    top = max(detections, key=lambda d: d.confidence)
    if top.class_name == self.config.pass_class:
        if top.confidence >= self.config.pass_conf_threshold:
            return ViewVerdict(verdict=PASS, ...)
        elif top.confidence >= self.config.uncertain_floor:
            return ViewVerdict(verdict=UNCERTAIN, ...)   # borderline good cap

    # 4. Anything else goes to review, never to an automatic pass
    return ViewVerdict(verdict=UNCERTAIN, ...)
\end{lstlisting}

\begin{lstlisting}[language=Python, caption={Fill-ratio computation}, label={lst:fill}]
@classmethod
def compute_fill_ratio(cls, bottle_bbox, water_bbox):
    bx1, by1, bx2, by2 = bottle_bbox
    bh = by2 - by1

    by1_corr = by1 + int(bh * cls.BOTTLE_TOP_TRIM)   # 0.03
    by2_corr = by2 - int(bh * cls.BOTTLE_BOT_TRIM)   # 0.02
    bottle_h_corr = max(by2_corr - by1_corr, 1)

    # Meniscus mid-line, clamped inside the trimmed bottle
    water_y = (water_bbox[1] + water_bbox[3]) // 2
    water_y = max(by1_corr, min(by2_corr, water_y))

    fill_from_bottom = by2_corr - water_y
    return round(float(fill_from_bottom / bottle_h_corr), 3)
\end{lstlisting}

\section{Data Collection Methodology}

\subsection{Secondary Data (DS-1 to DS-4)}
DS-1 to DS-3 were obtained from Roboflow Universe~\cite{roboflowcap,fillds1,fillds2} and other public sources under the CC BY 4.0 licence and used with their published splits. DS-1 was captured at $2048{\times}2048$ (a handful of images at $2048{\times}1536$) with one bottle neck and one cap per image against indoor backgrounds; its training split holds 2,486 source photographs, each exported in three augmented versions (rotation $\pm5^\circ$, brightness $\pm25\%$, blur up to 2\,px, 0.5\% salt-and-pepper noise), while validation and test images are not augmented. DS-2 merges four public bottle and cap sources into one bottle class. DS-3 combines two single-class liquid-surface sets. DS-4 is the four-class cap set from earlier project work, used only to benchmark whole-image classifiers.

\subsection{Primary Data (DS-5)}
DS-5 consists of 120 flat, unwrapped scans of the Himalaya Winter Defense Moisturizing Cream (50\,ml) tube label, about $1504{\times}8000$ pixels each, supplied by the industrial partner and labelled good or defective per scan. From these scans the team cut the four region templates, produced the per-region crops used to train and calibrate the anomaly models, and re-annotated the ROI\_4 defects. In addition, photographs of the team's own bottles were used during integration for a qualitative check of the deployed cap engine; they are not part of any reported metric.

\section{Composition and Class Distribution}
Table~\ref{tab:capdata} gives the per-class split of DS-1: good caps make up 56.9\% of the training images and misplaced caps 4.4\%, and the average majority-to-class ratio is 6.29 (Eq.~\eqref{eq:imb}). DS-2 has 2,286 / 417 / 280 images with 2,133 / 774 / 356 bottle boxes in training, validation, and test; DS-3 has 545 / 31 / 41 images with 1,683 / 54 / 76 surface boxes. DS-5 holds 78 good and 42 defective scans; the crop counts per region are given in Table~\ref{tab:label-colour}.

\section{Structure, Format and Annotation}
DS-1 follows the YOLO segmentation format: images in \texttt{train}, \texttt{valid}, and \texttt{test} folders, one text file per image with the class index and a normalised polygon per instance, and a \texttt{data.yaml} that names the six classes. DS-2 and DS-3 use the YOLO detection format (class index and normalised centre, width, and height per box). DS-5 scans are BMP files; the derived region crops are rotated upright and resized to $256{\times}256$. Annotation used Roboflow and LabelImg. The audit bundles written by the running system use the same YOLO formats, so reviewed inspections can be exported directly as training data.

\section{Limitations, Bias and Ethical Considerations}
\begin{itemize}
    \item \textbf{Annotation.} DS-1 masks come from a single annotator, so inter-annotator agreement cannot be measured. DS-5 labels are per scan, not per region, which dilutes region-level calibration.
    \item \textbf{Coverage.} DS-1 shows transparent PET bottles against indoor backgrounds; other bottle types, cap colours, and line lighting are under-represented. DS-5 covers one product and only flat, evenly lit scans.
    \item \textbf{Imbalance.} The cap classes are imbalanced, which is why class-sensitive metrics are reported (Section~\ref{sec:metrics}).
    \item \textbf{Ethics and licensing.} The public sets are used under CC BY 4.0 and cited. The images show products, not people, apart from incidental hands in a few fill-level frames. The DS-5 product images belong to the manufacturer and are used only for this project.
\end{itemize}

\section{Availability}
DS-1 to DS-3 are available from their public sources~\cite{roboflowcap,fillds1,fillds2}. The code and evaluation scripts are in the project repository (Section~\ref{sec:dataset}). DS-5 is not redistributed; it is held in the local project folder.
